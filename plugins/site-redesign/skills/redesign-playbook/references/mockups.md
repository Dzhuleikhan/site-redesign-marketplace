# Макеты на холсте

## Где

Холст типа Design (artifact). Найти тип через список типов артефактов (`list_types`), создать
ОДИН холст на весь редизайн с названием «<Проект> — редизайн» и дальше только дополнять его.
Инструкции типа приходят при создании — следовать им. Ссылку на холст записать в `.redesign/STATE.md`.

## Что рисовать на каждый вариант

| Артборд | Размер | Содержание |
|---|---|---|
| `V<n>Main.dc.html` | 1440 × по высоте, страница | Главная целиком: хедер, сайдбар, все секции из описи по порядку, футер. Тёмная тема |
| `V<n>MainLight.dc.html` | то же | Та же главная в светлой теме |
| `V<n>Auth.dc.html` | 960 × 640 | Модалка регистрации, тёмная (вход — те же поля, другая вкладка) |
| `V<n>AuthLight.dc.html` | 960 × 640 | То же, светлая |

Над рядом артбордов варианта — заметка-заголовок «Вариант N — <название языка>».
Варианты располагать рядами, не перекрывая существующие артборды.

## Правила макета

- Секции — ровно из описи структуры, в том же порядке, с теми же заголовками и текстами.
  Нет данных — плейсхолдер `[PARTNER]`, `[LICENSE TEXT]`, а не выдуманные цифры.
- Обложки игр — реальные: скриншот ряда карточек с dev-сервера, нарезанный в спрайт и
  загруженный как ассет холста. Арты, маскот, иконки — из Magnific (`magnific.md`).
- Каждый элемент, который потом пойдёт в код, нарисован явно: активный и обычный пункт меню,
  кнопки (основная, вторичная, ghost), табы, поля, чипы, бейджи, состояние live.
- Светлая версия — та же композиция; меняются фон, поверхности и цвета текста/акцентов,
  которые не читаются на светлом (например, жёлтый текст на белом заменить на тёмный акцент).
  Блоки с артом (hero, баннеры) могут остаться тёмными.
- Оба варианта отличаются и друг от друга по 4+ измерениям из `originality.md`, иначе выбирать
  не из чего.

## Отдать пользователю

Ссылку на холст (на артборды вариантов), таблицу оригинальности и по 3–4 строки на вариант:
палитра, шрифты, форма, фирменный приём. Спросить: «Какой вариант берём?»
