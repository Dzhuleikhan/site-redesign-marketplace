# Известные ловушки

Собраны на реальном редизайне. Не повторять.

1. **Перекраска вместо редизайна.** Первый результат сохранил форму блоков, типографику,
   декоративные полосы и карточки старого дизайна, поменяв только цвета, — пользователь увидел
   «тот же сайт». Решение: чек-лист `originality.md` применять и к ТЕКУЩЕМУ дизайну проекта,
   не только к референсам.
2. **Структуру меняли в макете.** Макет с переставленными блоками отклонён. Макет строится
   строго по описи.
3. **«Сделал по макету», а не сделал.** Код правили по памяти о макете и пропустили футер,
   нижние кнопки сайдбара, модалки и внутренности секций. Решение — поблочная сверка по
   `verification.md` с артбордом перед глазами.
4. **Светлая тема забыта.** Правки проверяли только в тёмной. Каждый блок — обе темы.
5. **Арты из старой палитры.** Новые цвета + старые арты = чужеродно. Перегенерировать под
   палитру варианта.
6. **Иконки на тёмной подложке** ломают светлую тему — генерировать на прозрачном фоне.
7. **Статика может не отдаваться локально** (часть путей обслуживает CDN/прокси). Картинку,
   которую надо проверить локально, импортировать статически рядом с компонентом.
8. **Глобальная замена строк** задевает кеш сборки (`.next`, `dist`) — менять только файлы
   под git.
9. **Несуществующие переменные/токены** молча ломают отступы и цвета — проверять имя в файле
   токенов перед использованием.
10. **Показ по внешней ссылке (ngrok и т. п.):** dev-сервер Next 16 не пускает чужой origin —
    `allowedDevOrigins` в конфиге (не коммитить); туннель запускать с подменой Host на
    `localhost`; старый service worker на том же домене туннеля может показать другой проект —
    проверять в инкогнито.
11. **Сеть.** Из песочницы доступны не все сайты; проверки ботов (Cloudflare и т. п.) не
    обходить — просить скриншот.
