# Перенос макета в код

Сначала прочитать навык `project-rules` и правила самого репозитория. Они главнее этого файла.

## Слои, сверху вниз

1. **Переменные темы.** Новые цвета, поверхности, радиусы, тени, фон страницы, акценты и
   фирменный мотив задать переменными (CSS-переменные, токены темы, конфиг Tailwind — что
   принято в проекте) отдельно для каждой темы. Сгенерированные токены не править руками —
   переопределять уровнем выше. Всё, что зависит от темы, — только через эти переменные.
2. **Шрифты.** Подключить так же, как в проекте подключены нынешние (везде, где они
   подключены: корневой layout, тема UI-библиотеки, письма/ошибки — по необходимости).
   Проверить наличие нужных алфавитов (например, кириллицы) и весов. Регистр и курсив
   менять через токены типографики, если они есть, а не в каждом месте.
3. **Общие компоненты** (UI-кит, дизайн-система): кнопки, карточки, заголовок секции, меню,
   футер, табы, поля. Менять их стили и, где нужно, добавлять проп-вариант — родитель не
   переопределяет внутренности ребёнка селекторами. Общий компонент виден на всех страницах:
   это и нужно для редизайна, но проверять придётся шире.
4. **Блоки страниц**: композиция под макет, новые арты рядом с компонентом со статическим
   импортом, если проект так делает.

## Порядок для главной

Каркас (переменные темы → шрифты → хедер → сайдбар → футер) → секции главной сверху вниз →
модалки входа/регистрации → мобильная навигация. После каждого блока — сверка
(`verification.md`), потом следующий.

## Запреты

- Не менять логику разметки: обработчики, данные, условия показа, `data-testid`, ключи переводов.
  Разрешено: классы, стили, обёртка только когда без неё нельзя.
- Не менять порядок секций и состав страниц.
- Не трогать то, что по правилам проекта править нельзя (апстрим, сгенерированное).
- Тесты, которые проверяют разметку блока, прочитать перед правкой и не ломать.
- Не запускать менеджеры пакетов и git-записи. Проверки запускает человек.

## Отчёт после шага

1–2 предложения что сделано + раздел «расхождения с макетом» (честно, с причиной) +
напоминание запустить проверки. Не пересказывать дифф.
