# Код всего сайта по Figma

Код пишется ТОЛЬКО по утверждённым фреймам. Нет фрейма — не верстать, а вернуть пакет на шаг
`redesign-figma`. Живой сайт — источник структуры и логики, но не внешнего вида.

1. Прочитать `.redesign/STATE.md` (фреймы, утверждение дизайна). Не утверждён — спросить и
   остановиться.
2. Прочитать `project-rules` целиком и из `redesign-playbook`: `lessons.md`,
   `implementation.md`, `verification.md`, раздел «Этап кода» в `figma-pipeline.md`.
3. Убедиться, что пользователь на нужной ветке; ветку не создавать и не переключать.
4. Пакеты по одному агенту, в порядке: переменные темы и шрифты → общий кит → хром (шапка,
   сайдбар, футер, мобильная навигация) → главная → страницы по разделам → модалки.
   Агент читает свои фреймы через `get_design_context`, правит только свои файлы.
5. После каждого пакета: проверки репозитория (только если пользователь разрешил), затем
   сверка в браузере с фреймом по `verification.md` — 1440 и 375, в темах, выбранных на шаге
   `redesign-figma` (записаны в `.redesign/STATE.md`). Если выбрана одна тема, вторую в коде
   не трогать и не ломать — спросить, нужна ли она вообще. Расхождение —
   чинить, не описывать.
6. **Ревью кода** отдельным агентом: каждый маршрут из описи покрыт, от старого вида ничего не
   осталось (старые картинки, стили, классы), правила `project-rules` соблюдены.
7. Отчёт: таблица «страница — код — сверка — расхождения», что не проверено и почему,
   напоминание про typecheck/lint/тесты. Обновить `.redesign/STATE.md`.

**Жёсткий запрет:** кодер меняет только внешний вид. Логику и поведение не трогать никогда:
шаги и сценарии, обработчики, условия отправки/закрытия/перехода, хуки, состояние, загрузку
данных, смысл пропсов, добавление или удаление интерактивных элементов, блоков и текстов.
Если фрейм подразумевает другое поведение — оставить поведение кода и назвать разницу в
отчёте. Перед сдачей агент сравнивает каждый тронутый файл с HEAD и откатывает всё, что не
относится к виду; в отчёте обязателен раздел «Проверка поведения».

**Набор элементов как в исходном проекте:** ничего не добавлять и не убирать — ни кнопок,
ссылок, крошек и крестиков, ни текстов и ключей переводов (новые ключи с тем же текстом
запрещены), ни анимаций и навигации. Есть — остаётся в новом виде; нет — не появляется.

**Финал:** удалить файлы, ставшие неиспользуемыми (только после проверки импортов),
обновить тесты под новый вид, подтянуть свежую базовую ветку и прогнать проверки
репозитория. Порядок и детали — в `lessons.md` (пункты 16–23).

Половинчатых правок не бывает: страница переписывается целиком по фрейму или не трогается.
